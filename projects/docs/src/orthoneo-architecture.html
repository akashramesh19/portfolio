1. System Overview

This engagement replaced Orthoneo's existing VIPsites builder with a self hosted WordPress CMS, built on a custom theme and a small set of custom plugins. The goal was not just a new website, but a system the client's non technical staff could run independently after handover.

WordPress runs on the client's existing VentraIP Select Hosting Shared plan, so the migration carried zero additional hosting cost. Staff manage all content through the WordPress admin dashboard, with Elementor available for layout level changes within the boundaries the custom theme sets.

3. Infrastructure Design

WordPress was installed on the client's existing VentraIP Select Hosting Shared plan, the same plan that previously ran VIPsites. This meant the migration carried zero additional hosting cost, since no new hosting product or upgrade was required.

Hosting level configuration, including DNS records and server settings, was managed through cPanel and VentraIP's VIPcontrol panel. Both were configured as part of the migration, alongside the WordPress installation itself.

4. Theme Architecture

The custom theme defines the brand and layout structure: colours, typography, header and footer structure, and the templates for each content type the business uses. These are the boundaries staff do not change day to day, which keeps the site visually consistent as content is added or updated.

Elementor sits on top of the custom theme as the page builder layer. Staff can use it to rearrange sections, adjust layout, and build new pages within the constraints the theme sets, without needing to edit any theme code directly.

5. Plugin Architecture

The custom plugins handle the specific product and content management features the business needed, the kind of functionality a generic theme or a page builder alone does not provide. Building this as a plugin set, rather than as functions bundled into the theme, keeps the functionality independent of the theme. It can survive a future theme change or update without needing to be rebuilt.

Each plugin gives staff a straightforward admin interface for the content type it manages, so day to day product and content updates do not require touching code or contacting a developer.

6. Content Management Model

Staff manage day to day content, including product information and page text, directly through the WordPress admin dashboard, using the interfaces the custom plugins provide.

Layout level changes, such as rearranging sections on a page, go through Elementor within the constraints the custom theme sets.

Changes outside those boundaries, such as a new content type or a structural template change, still require developer involvement. That boundary was scoped deliberately during handover, so staff know what they can change directly and what needs to come back to a developer.

8. Next Phase Architecture

Retainer scoping is in progress for the next phase. Two integrations are planned:

HotDoc booking integration would connect the site to HotDoc's booking API, so patients and referrers can book directly from the site rather than through a phone call. The integration would sit alongside the existing custom plugin set, calling the HotDoc API with a scoped API key rather than exposing any booking logic to the browser directly.

The AI powered FAQ chatbot would use the Claude API to answer common procurement and product questions on the site. The chatbot would call the Claude API from the backend, with the API key held server side, and would be scoped to the business's own product and policy content rather than open ended conversation.

Neither integration is live yet. Both are scoped for the next phase of the engagement.
